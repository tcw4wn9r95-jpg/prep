# Evidence for the n-rule trigger set

Generated by `node pipeline/test/nrule-evidence.js --write`. Do not edit by hand.

The Eifeler Regel drops a word-final `n` unless the next sound is one of a small set. `pipeline/lib/nrule.js` hard-codes that set, so this table exists to show it was measured rather than recalled - and to make a future LOD release able to contradict it.

## Method

Take every adjacent word pair in the `<text>` example sentences of the LOD search index. Group by the first letter of the second word, and measure what share of those pairs have a first word ending in `-n`. Where the rule keeps the `n`, that share is high; where the rule drops it, only the words whose `n` is stem-final survive, so the share collapses.

Corpus: 455,751 adjacent pairs, 75,320 with an `-n` first word.

The split is clean, with no letter in between: **t, é, d, ä, z, a, u, i, h, e, n, o, ë** keep the `n`, **w, s, f, v, m, g, k, b, j, r, c, l, q, p** drop it. That is `n d t z h` plus the vowels, which is the set `TRIGGER_CONSONANTS` and `VOWELS` encode.

## What this table does not settle

- **Pronunciation, not spelling, drives the rule.** Numerals (`20` = *zwanzeg*), initialisms (`CV` = */tseːveː/*) and single letters are read aloud, so their written first character predicts nothing. `hasOpaqueOnset` skips them.
- **LOD is not internally consistent.** Before `sech`, `se` and the `sen-` possessives it writes both forms. `build-corpus.js` measures that variation and downgrades those contexts to warnings; the table lands in `content/lexicon.json` under `nRuleRetentionExceptions`.
- **Homographs break the reverse direction.** `A` the noun looks like `a`, the dropped form of `an`; `Wee` looks like `wee(n)`. Flagging a *missing* `n` therefore only ever warns.

Run `node pipeline/test/calibrate.js` for what all of that costs on LOD's own sentences.
